# Workspace notes

Per-feature `spec.md` files are the source of truth. `product.md`, `dashboard.md`,
`analyze-product.md`, and `view.html` are generated, never hand-written:

    node scripts/assemble.mjs
    node scripts/dashboard.mjs
    node scripts/view.mjs

`constitution.md` and `product-global.md` are main-branch-only. Editing either one restages
every feature's pre-build check, so change them deliberately and on their own.

Start a new feature with `/spec-flow:feature`, or run `/spec-flow:flow` to be guided.

## Why these settings

- **`requires_design: false`** — most of this product is a library, a CLI, and adapters, where a
  separate design artifact is dead weight. The browser interface sets `requires_design: true` in
  its own manifest, so the design stage still gates the one feature that needs it.
- **`default_depth: mvp`** — the whole product is specified before implementation, so features
  must pass the code-against-spec audit before they count as done, and acceptance criteria must
  be covered by tests. Reserved `ga` for contracted or regulated work, which this is not.
- **`board.mode: none`** — single developer. Build order comes from each feature's dependencies,
  not from time-boxed sprints.
- **`tests`** — pytest layout under `tests/`, matching the Python and `uv` decision in the brief.
